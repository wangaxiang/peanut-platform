#### ▶ 第三项：模块四 · 智能分析与处方图生成（规格文档第 5 节）

#### ▶ 第四项：模块五 · 水肥一体化远程管控（规格文档第 6 节）
提交信息：`feat(irrigation): 完成模块五-水肥一体化控制（后端+前端）`

后端实现内容：
- `IrrigationDevice` 实体 + Repo + Service + Controller；`last_seen_at` 字段由 MQTT 心跳消费者每次收到设备上报时更新，同时将 `online` 置 true；定时任务每 90 秒扫描一次，`last_seen_at` 超过 90 秒的设备 `online` 置 false
- `IrrigationTask` 实体 + Repo + Service + Controller
- `POST /api/irrigation/tasks`：接收 `{fieldId, deviceId, zoneIds, triggerType, waterAmountM3, fertilizer:{nKg,pKg,kKg,concentrationPct}, durationMin, scheduledAt?}`，写库 status=pending，立即或按 scheduledAt 通过 MQTT 下发规格文档 6.2 节的指令至 `irrigation/{device_sn}/cmd`
- `POST /api/irrigation/devices/{id}/control`：手动控制，接收 `{action:"start"|"stop", zones:[1,2]}`，直接发 MQTT 指令，不写 task 表
- MQTT 消费者：监听 `irrigation/+/status`，解析 phase/zones/totalWaterM3，实时更新 irrigation_task 状态；phase=done 时写 finished_at 和实际用水量；phase=fault 时 status 改为 failed
- WebSocket：后端用 Spring WebSocket（STOMP），设备状态变更时 broadcast 至 `/topic/field/{fieldId}/irrigation`，payload 含阀门开关状态和实时流量
- `IrrigationAutoTriggerJob`：按规格文档 6.3 节实现，每 10 分钟执行，查 InfluxDB 最新 soil_moisture，低于阈值且 24 小时内未触发则自动创建 triggerType=sensor 的任务
- `GET /api/irrigation/tasks?fieldId=&page=`：分页，含 status/实际用水量/触发方式

前端实现内容：
- IrrigationControl.vue：页面主体是设备分区示意图（SVG 矩形代表每个分区），每个分区显示阀门开/关状态（绿色=开/灰色=关）和实时流量数字；通过 WebSocket 订阅 `/topic/field/{fieldId}/irrigation`，状态自动刷新，无需手动点击；每个分区有独立的"开"/"关"按钮调用 POST /control 接口
- IrrigationTaskForm.vue：弹窗表单，含分区多选（checkbox）、灌溉量输入（m³）、持续时长（分钟）、N/P/K 配比（三个数字输入框）、定时时间（DateTimePicker，可空表示立即执行）
- IrrigationHistory.vue：表格展示任务历史，列：触发方式（人工/定时/传感器，不同 icon）/ 分区 / 计划用水量 / 实际用水量 / 状态 / 开始时间 / 结束时间；点击行展开施肥配方详情

验收测试步骤：
1. 创建一条灌溉任务 → EMQX 收到 `irrigation/{sn}/cmd` 指令
2. 模拟设备上报 `phase=running` → 前端 IrrigationControl 页面阀门图标变绿，流量数字更新（无需刷新）
3. 模拟设备上报 `phase=done` → 任务状态变为 done，finished_at 写库，实际用水量出现在历史列表
4. 断开模拟设备 90 秒 → 设备列表中 online 变为 false
5. 手动触发 IrrigationAutoTriggerJob → 确认低湿度地块产生一条 triggerType=sensor 的任务
