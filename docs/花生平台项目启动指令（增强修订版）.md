后端实现内容：

- `POST /api/irrigation/tasks`：接收 `{fieldId, deviceId, zoneIds, triggerType, waterAmountM3, fertilizer:{nKg,pKg,kKg,concentrationPct}, durationMin, scheduledAt?}`，写库 status=pending，立即或按 scheduledAt 通过 MQTT 下发规格文档 6.2 节的指令至 `irrigation/{device_sn}/cmd`

- `IrrigationAutoTriggerJob`：按规格文档 6.3 节实现，每 10 分钟执行，查 InfluxDB 最新 soil_moisture，低于阈值且 24 小时内未触发则自动创建 triggerType=sensor 的任务

- IrrigationTaskForm.vue：弹窗表单，含分区多选（checkbox）、灌溉量输入（m³）、持续时长（分钟）、N/P/K 配比（三个数字输入框）、定时时间（DateTimePicker，可空表示立即执行）
- IrrigationHistory.vue：表格展示任务历史，列：触发方式（人工/定时/传感器，不同 icon）/ 分区 / 计划用水量 / 实际用水量 / 状态 / 开始时间 / 结束时间；点击行展开施肥配方详情

验收测试步骤：

2. 模拟设备上报 `phase=running` → 前端 IrrigationControl 页面阀门图标变绿，流量数字更新（无需刷新）

4. 断开模拟设备 90 秒 → 设备列表中 online 变为 false
5. 手动触发 IrrigationAutoTriggerJob → 确认低湿度地块产生一条 triggerType=sensor 的任务

## 注意事项（每个模块都适用）

1. **代码风格**：Java 用驼峰命名，Python 用下划线命名，前端组件用 PascalCase。
2. **先审计再实施**：任何阶段开始前确认代码、数据库迁移、依赖和未提交修改；不确定时先报告，不猜测。
3. **后端与前端必须成套交付**：接口、数据模型、页面、交互、错误态、测试和浏览器验收缺一不可。
4. **界面质量要求**：专业、直观、现代的农业 SaaS 控制台；信息层级清晰、留白合理、统一状态色、图表单位/图例/tooltip/阈值线齐全；避免堆砌卡片和纯装饰动画。
5. **不要跳步骤**：每阶段必须通过对应验收标准；测试失败不得标 `[x]`。
6. **遇到问题**：依赖安装失败、端口冲突、数据库迁移风险或真实设备协议不明确时，先告诉我具体报错/风险，不要擅自换依赖、改端口或猜协议。
7. **模拟不等于真实**：模拟设备和模拟遥测必须明显标识，不能声称已连接真实硬件。
8. **不要提前实现**：每次提交只包含当前阶段范围；模块二增强阶段不顺手开发模块三/四/五。
9. **每次等我确认**：每阶段完成后汇报并停下，只有我说“继续”才能进入下一阶段。
10. **Git 安全**：只在 dev 开发；未经我确认不得合并 main、打 tag 或宣称推送成功。
